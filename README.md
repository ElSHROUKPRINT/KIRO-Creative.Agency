# KIRO Creative Agency — الموقع كامل (النسخة v2: جاهزة للنشر)

فرونت اند (HTML/CSS/JS) + باك اند Node.js/Express بيقدّم الموقع، ولوحة التحكم، وبيسجّل الطلبات والحجوزات.

## رفع المشروع على GitHub

1. فك الـ zip وارفع الملفات كلها مباشرة على الريبو (كلها في مستوى واحد، مفيش مجلدات) — لازم `index.html` يظهر في أول صفحة الريبو.
2. **GitHub Pages** (Settings → Pages → Deploy from a branch → `main` / `(root)`): بيفتح الواجهة فقط كنسخة عرض. الحجز ولوحة التحكم والطلبات محتاجين باك اند، فمش هيشتغلوا على Pages.
3. للموقع الكامل شغّال: انشر الريبو على Render (فيه `render.yaml` جاهز) أو Railway، وحط `ADMIN_PASSWORD` و`SITE_URL`.

## البنية

```

api.test.js · frontend.test.js · helpers.js   ← 22 اختبار
```

## التشغيل محليًا

يتطلب Node.js 18+ (يفضّل 20+).

```bash
npm install
cp .env.example .env      # عدّل القيم (في التجربة المحلية خلي NODE_ENV=development أو امسح السطر)
npm start                 # → http://localhost:3000
```

لو ما حطتش `ADMIN_PASSWORD` في وضع التجربة، بيتولّد باسورد ويتطبع في الشاشة ويتحفظ في `data/GENERATED_ADMIN_PASSWORD.txt`.
**في production السيرفر بيرفض يشتغل من غير `ADMIN_PASSWORD` (12 حرف+).**

> لو عندك `db.json` قديم من النسخة السابقة: حطه في `data/` قبل أول تشغيل. السيرفر هينظّفه ويحوّل أي صور base64 لملفات تلقائيًا (وبياخد نسخة احتياطية قبل الترحيل).

## استخدام لوحة التحكم

1. افتح `https://موقعك/#/admin` واكتب كلمة السر (الجلسة بتفضل 8 ساعات، وبتتخزن في Cookie مؤمَّنة — مش بتتخزن في المتصفح).
2. عدّل ما تريد: الهوية، المدرسين، الأعمال، آراء العملاء، المناسبات والخصومات، الأسعار، النصوص. أي تعديل بيتحفظ على السيرفر تلقائيًا وتظهر رسالة «اتحفظ على السيرفر وظاهر للزوار ✔» — لو ظهرت رسالة خطأ، التعديل **ماوصلش** (هيحاول تاني تلقائيًا).
3. تبويب **الطلبات**: كل حجز/تواصل/طباعة/اشتراك بيتسجّل هنا. غيّر الحالة (جديد/مؤكد/تم/ملغي). **«ملغي» بيفتح ميعاد الحجز تاني.** زر «تصدير CSV» بيفتح في Excel.
4. رفع الصور بيتم لملف على السيرفر (حد أقصى 2.5MB بعد الضغط التلقائي). لو حد تاني عدّل في نفس الوقت هتظهرلك رسالة وتتحمّل أحدث نسخة (عشان محدش يمسح شغل التاني).
5. «تصدير/استيراد» في لوحة الأدمن بياخد/يرجّع نسخة كاملة من بيانات الموقع.

## النشر (Deploy)

| الخطوة | التفاصيل |
|---|---|
| 1. متغيرات البيئة | `NODE_ENV=production` · `ADMIN_PASSWORD` (12+) · `SITE_URL` · `TRUST_PROXY=1` · `DATA_DIR` |
| 2. أمر التشغيل | `npm ci --omit=dev && npm start` |
| 3. تخزين دائم | اربط Disk/Volume وحط مساره في `DATA_DIR` (بدونه الداتا والصور بتتمسح مع كل deploy على Render/Railway/Heroku) |
| 4. HTTPS | إجباري (الكوكي `Secure` بتتفعّل لوحدها). الأفضل Cloudflare قدّام الموقع (CDN + gzip/brotli + حماية DDoS مجانًا) |
| 5. Instance واحد | الجلسات والداتا في ذاكرة/ملفات السيرفر — شغّل instance واحد (كفاية آلاف الزوار). للتوسع الأفقي انظر «التطوير المستقبلي» |

مثال Render: Web Service · Build `npm ci --omit=dev` · Start `npm start` · Disk مسار `/var/data` مع `DATA_DIR=/var/data`.

**الدومين والتليفون والتتبّع بيتحقنوا تلقائيًا** من `SITE_URL` والداتا و`GA_MEASUREMENT_ID` / `META_PIXEL_ID` — مفيش داعي تعدّل `index.html` يدويًا. التتبّع مابيشتغلش إلا بعد موافقة الزائر (بانر).

## النسخ الاحتياطي والاسترجاع

- كل حفظ بيعمل نسخة من الحالة **السابقة** باسم فيه التاريخ والوقت (`backups/db-2026-10-03T14-22-10-123Z.json`) — مفيش نسخة بتتكتب فوق التانية. بتتحفظ 14 يوم (وآخر 30 نسخة على الأقل).
- `npm run backups` ← عرض النسخ · `npm run restore -- <اسم-الملف>` ← استرجاع (أوقف السيرفر الأول).
- انسخ مجلد `DATA_DIR` كله (فيه الصور والطلبات) بشكل دوري لمكان خارج السيرفر.
- `audit.log` بيسجل كل دخول/حفظ (بيتدوّر تلقائيًا عند 2MB).

## الأمان — ما اتعمل

- جلسات HttpOnly + SameSite=Strict (الباسورد مابيتخزنش في المتصفح)، مقارنة constant-time، تأخير على الفشل، Rate limit للدخول (8 محاولات فاشلة / 15 دقيقة / IP — الناجحة مش بتتعد).
- Validation بـ whitelist لكل الداتا (أنواع، أطوال، روابط http/https فقط، ألوان/ids محددة)، صور بتتفحص بالـ magic bytes، فرض `_v` ضد الكتابة المتعارضة.
- فرونت: كل نص جاي من الداتا بيتعمله escape، وكل رابط/صورة بتتفحص، والـ HTML المسموح محصور في `<b> <i> <strong> <em> <br>`.
- Helmet + CSP، HSTS في production، إخفاء `X-Powered-By`، رسائل أخطاء بدون تفاصيل داخلية.

## حدود معروفة (بصراحة)

- **CSP فيه `'unsafe-inline'` للسكريبتات** لأن الـ HTML فيه onclick/scripts inline. الحماية الأساسية من XSS هي الـ escaping + الـ validation (واتختبرت)، لكن لو عايز CSP صارم لازم تنقل الـ inline handlers لـ `app.js` وتستخدم nonces.
- **أدمن واحد بباسورد واحد**، والجلسات في الذاكرة (إعادة تشغيل السيرفر = تسجيل دخول تاني). مفيش 2FA.
- **الداتا في ملفات JSON** (كفاية جدًا لموقع استوديو). لو هتشغّل أكتر من instance أو حجم طلباتك كبير: انقل لـ SQLite/Postgres.
- **الحجز بيمنع تكرار الميعاد في نفس الفرع**، لكن مفيش تقويم/تأكيد تلقائي — التأكيد بيتم يدويًا من تبويب الطلبات وواتساب.
- مفيش دفع أونلاين. الأسعار المحسوبة في المتصفح **تقدير للعميل**؛ السعر النهائي بيتأكد في واتساب.
- نقاط الكسر (breakpoints) في CSS كتير ومتفرقة (لسه مااتوحّدتش) — شغالة، بس الصيانة أصعب. Font Awesome بيتحمّل كامل من CDN (ممكن تعمله subset لتوفير ~70KB).
- الأداء على 120/144Hz اتحسّن بالكود (حركة مربوطة بالزمن + إيقاف الحلقات خارج الشاشة)، لكن **ماتقاسش بجهاز حقيقي** هنا — جرّب Chrome DevTools → Performance على جهاز 120Hz.
